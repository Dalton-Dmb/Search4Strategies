# AlphaIQ™ Handoff Scope and Authority

The handoff documents are intended to make the repository self-contained for a successor developer. In case of conflict, executable safety invariants/tests and the production-first AlphaIQ™ architecture take precedence over convenience changes. Material trading-rule, risk-policy and live-release decisions must not be silently changed by a successor.

The successor is authorised to solve ordinary engineering problems, refactor safely, add tests, improve packaging, fix CI, and implement already-approved specifications without repeatedly seeking permission. The successor must escalate missing proprietary strategy definitions, external credentials/licensing, genuinely new material risk/product choices, independent-audit requirements and live-release authorisation.

The target is not a demonstration script. It is one versioned system capable of research→replay→paper→shadow→authorised-live progression through configuration and release gates, without fundamental rewrite.
