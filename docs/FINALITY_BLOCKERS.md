# AlphaIQ™ Finality Blocker Register

These are not reasons to stop ordinary development; they are inputs/gates that cannot be fabricated by a successor.

| Blocker | Why external | Work that can continue meanwhile |
|---|---|---|
| Exact missing proprietary strategy source | Rules must not be invented | packaging, data adapter, existing certified engines, tests |
| Historical provider/files/rights | genuine evidence requires approved data | provider-neutral adapter, fixtures, quality tooling |
| Broker/demo credentials | supplied out-of-band | broker-neutral contracts, simulators, recovery tests |
| Contabo access | external host | Docker/compose/runbook/CI locally |
| Independent reviewer | independence cannot be self-certified | prepare audit dossier/evidence |
| Explicit live authorisation | owner release decision | research/paper/shadow deployment |

A successor report should name the exact missing input and continue all non-blocked work. It should not ask for a generic “proceed” instruction.
