# AlphaIQ™ No-False-Completion Rule

A milestone may be called **implemented** when its code/contracts/tests exist. It may be called **empirically validated** only when genuine applicable evidence has been run through those contracts. It may be called **independently audited** only after an independent reviewer supplies the required dossier evidence. It may be called **deployment-ready for a requested mode** only when that mode's release gates pass. It may be called **LIVE authorised** only after explicit owner authorisation.

These states are deliberately separate. Passing unit tests for an analytical function is not evidence of trading profitability; a container starting successfully is not empirical validation; an OOS-report capability with no genuine observations is not an OOS performance result.
